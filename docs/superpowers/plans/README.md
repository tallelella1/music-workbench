## 开发顺序

1. [基础播放器实施计划](2026-10-03-music-player-implementation.md)：Windows 桌面应用、本地曲库与歌单、播放与音效、裁剪导出、多平台搜索及 LX 音源接入。
2. [AI 音频编辑实施计划](2026-10-03-ai-audio-editing-implementation.md)：本地指标与节拍分析、API 规划、参数预览、响度对比、撤销恢复与导出。
3. [模板与节奏动效实施计划](2026-10-03-music-visual-implementation.md)：图片与主体遮罩、固定图层、局部编辑、上下 Q 弹、PNG/JPEG/MP4/GIF 导出。

基础播放器先提供素材注册、可取消任务、播放时间轴、效果注册表和音频导出接口。AI 音频单元再提供创作版本、BeatMap 和 AIProvider，视觉单元复用这些接口。先后关系是接口依赖，不代表必须将所有功能压进一次发布。

执行方式：每个任务由子 Agent 实现，主 Agent 协调共享契约；任务结束后由独立子 Agent 审查。每个单元验收后进入下一单元，避免多个实现者同时修改共享文件。

## 本轮确定的实现选择

- 使用 Electron + React + TypeScript；electron-vite 构建，Vitest 验证业务规则，Playwright 验证真实 Electron 流程，electron-builder 生成 Windows 安装包。
- 所有文件访问、平台请求、密钥和 FFmpeg 任务由桌面宿主管理。界面通过具体操作与不透明素材 ID 访问资源。
- 不可信 LX 脚本放在独立、启用沙箱且无 Node 集成的隐藏渲染进程；宿主在进程外控制超时与终止。
- 实时音效与离线导出共用参数结构和混响脉冲响应；每种效果分别声明支持的实时与导出能力。
- 首个远程 AI 适配器计划采用 Gemini：文字规划、音频输入和图像编辑分别配置模型和探测能力。模型 ID 由设置指定，未配置时保留手动编辑。供应商适配器可以替换。
- 默认视觉模板以固定背景、独立文字和单一主体为核心。主体只上下移动与轻微挤压拉伸；暂停、定位、变速均以源音频时间为准。
