# Windows 音乐播放器设计规格

日期：2026-10-03（Asia/Hong_Kong）

状态：设计讨论稿，供用户审阅。用户已明确本阶段仅 brainstorming，不进行编码或进入实施。当前目录尚无产品代码；本文描述拟实现的功能和契约，不代表软件或平台完整音源已经交付。

## 1. 用户目标与范围

制作一个 Windows 桌面音乐播放器，提供接近 Apple Music 的简洁音乐库、专辑、歌单与播放体验。支持本地音乐导入、内置搜索、音色和播放速度调节，以及本地音频裁剪和效果导出。

新增两个音乐配套创作模块：AI 音频分析与参数编辑，以及模板封面和节奏动效编辑。用户已选择 AI 音频第一阶段为分析后自动调整 EQ、混响、动态和速度；图像用于音乐配套，默认动态效果为主体仅上下 Q 弹，可随音乐节奏调整。本阶段形成设计，不安装产品依赖、编写产品代码、调用收费生成接口或编写执行计划。

新增模块分别定义独立规格，共享素材、项目版本、任务状态和接口约定：

- [AI 音频编辑设计](2026-10-03-ai-audio-editing-design.md)
- [模板图像与节奏动效设计](2026-10-03-template-music-visual-design.md)

功能按基础播放器、AI 音频编辑、音乐视觉编辑三个交付单元规划；每个单元分别评审与验收。本文已有的“首版”播放器功能指基础播放器单元，新增创作单元的第一阶段范围以对应规格为准，不推定所有功能同时进入首版。

在线曲目以网易云、酷狗、QQ 音乐的聚合搜索为重点，预留酷我、咪咕等来源的接入位置。用户明确要求完整曲目播放，不提供试听播放或用试听代替完整音源。参考 LX Music 的搜索、曲目信息、音源脚本和换源机制。

后续能够独立增加音乐平台、播放音源、音效、导出格式和界面功能。兼容性设计的目标是提前发现接口不匹配、限制故障影响范围，并保留可恢复的数据；不承诺所有第三方接口和未来插件永久兼容。

尚待实际音源接入验证的事项：每个平台的完整播放覆盖范围、账号权限、音源脚本支持范围以及音源真实质量。2026-10-03 已进行公开搜索请求测试：网易云、酷狗、QQ 均返回曲目信息。搜索成功不等于完整播放已经验证。

## 2. 实现方案

采用 Electron + React + TypeScript 构建桌面应用。播放和实时音效使用 Web Audio；音频解析、必要的格式转换和本地导出使用 FFmpeg 工具链。依赖在实现时选用维护中的稳定版本并锁定，升级时执行相应兼容检查。

代码采用一个应用内的模块划分。首版通过接口和注册表扩展内置功能，外部动态扩展先限定为音源脚本；不在首版引入插件市场、任意界面插件或分布式服务。

界面层只依赖应用服务和统一歌曲模型。平台返回的原始数据、平台鉴权和 LX 字段转换均由接入层处理。搜索、完整性检查和换源不包含在界面组件内。

Electron 渲染页面启用 contextIsolation 和进程沙箱，不启用 Node 集成。preload 仅提供具体的应用操作，校验消息参数和调用来源，不暴露任意 IPC、文件读写或命令执行入口。

## 3. 模块边界

- UI：音乐库、搜索、专辑、歌单、播放条、音效编辑和设置页面，通过应用服务读写状态。
- LibraryService：本地文件索引、去重、歌曲信息、收藏和歌单；独立于在线平台。
- SearchService：查询多个 SearchProvider，处理分页、取消、缓存、平台状态和结果合并。
- PlaybackResolver：调用 PlaybackProvider，检查音源、曲目身份和完整性，执行音质协商与换源。
- PlayerEngine：接收已通过检查的播放资源，负责播放、暂停、定位、速度、音量、队列和播放事件。
- EffectChain：管理实时音效顺序、参数与启停，不直接访问平台接口。
- ExportService：使用 Exporter 对可编辑的本地资源进行裁剪、音效处理和编码；导出能力独立于在线播放能力。
- StorageRepository：保存版本化的曲库、歌单、设置和扩展配置，执行数据迁移。
- ExtensionHost：加载声明的扩展、验证兼容版本、运行音源兼容层，并维护各扩展运行状态。
- AudioAnalysisService / AIEditingPlanner：分析可编辑音频并生成结构化参数方案，连接现有 EffectChain 与 ExportService。
- TemplateService / VisualRenderService：管理图像模板、局部编辑、静态合成和动画渲染，通过音频时间轴驱动默认上下 Q 弹。
- CreativeProjectService：管理创作素材、不可变版本、撤销重做和远程任务状态，不改变 Track 与音乐平台的身份规则。

## 4. 扩展契约

### 4.1 搜索平台 SearchProvider

统一提供 search、可选的歌曲详情、专辑及歌单查询。输入包含搜索词、分页参数和取消信号；输出包含标准歌曲对象、总量或下一页标识，以及平台状态。

每个平台保留独立的平台 ID、认证配置、请求实现、字段转换和测试样本。新增平台通过注册新的适配器接入，播放器和已有平台不需要理解新平台的原始字段。

### 4.2 播放音源 PlaybackProvider

统一提供 resolve 和 capabilities。输入为平台歌曲引用、所需音质、播放目的和取消信号；输出为地址或资源句柄、请求所需信息、有效期、声明的音质及完整性信息。

返回地址后的验证由核心 PlaybackResolver 统一执行。插件不得自行宣称跳过完整性检查，也不直接操纵播放队列或歌单数据。

### 4.3 音效 AudioEffect

每种音效具有固定 ID、参数结构版本、默认参数、启停状态、参数更新方式和释放方式。实时播放和离线导出分别声明支持情况。

首版提供 10 段均衡器、音色预设和混响。0.5–2 倍播放速度及保持音高由 PlayerEngine 管理。预留升降调、压缩器、声场等独立音效位置。

调整音效参数时使用平滑过渡。加载失败的音效退出音效链，恢复已知可用的链路并给出具体原因，不直接中断其他模块。预设记录各音效参数版本，升级后执行参数迁移。

### 4.4 导出格式 Exporter

统一提供格式能力、参数检查、导出任务、进度和取消操作。首版提供 MP3、FLAC、WAV；MP3 可选择 128/320 kbps，WAV 提供实际支持的位深选项。

本节 Exporter 是音频导出契约，在新增创作规格中记为 AudioExporter。VisualExporter 使用独立的图层与时间轴输入契约，两者共享任务状态管理，不混用音频与图像输入结构。

导出任务使用独立工作进程，界面通过任务 ID 取得状态。新增编码器或格式不会改变 PlayerEngine 的接口。失败或取消时清理本次未完成的输出，原始文件保留。

### 4.5 应用功能 AppModule

首版使用编译进应用的模块注册表，统一声明路由、菜单、命令、所需能力和设置结构。预留歌词、歌单格式导入、WebDAV、云同步等后续模块位置，不在首版实现这些额外功能。

界面模块通过应用服务操作数据。未来如需要第三方界面插件，再根据实际需求确定独立的宿主边界，不将当前音源脚本协议扩大为任意应用插件协议。

### 4.6 AI 服务 AIProvider

独立声明文字规划、音频理解、图像理解、参考图编辑、局部编辑、多轮修改和任务查询等能力。每种能力分别定义输入输出结构和版本；某个模型支持音频理解，不推定它支持图像编辑。可替换的适配器负责各服务的上传格式、请求参数、任务 ID 和输出转换。

AI 产出的编辑方案包含素材 ID、基准版本、操作列表和参数，不直接执行模型返回的代码或未经注册的处理器。系统检查参数、能力、锁定区域和版本后应用到可撤销的预览版本。API 账号配置与 LX 音源配置隔离。

### 4.7 视觉模板与动画 VisualTemplate / AnimationRenderer

模板声明画布、图层、替换槽位、主体遮罩、布局约束、文字与背景锁定区域及可调参数。动画渲染器声明支持的图层类型、时间轴、可调动画参数和导出能力。模板版本、动画参数版本和 AIProvider 版本分别管理。

默认动画使用上下位移与轻微挤压拉伸，跟随 PlayerEngine 的源音频时间轴和节拍信息。固定背景、文字和用户锁定区域由本地合成器保持；AI 图像修改不承担逐帧节拍同步。后续新增动画模板通过注册渲染器与模板接入。

## 5. 标准歌曲与资源模型

Track 包含应用内稳定 ID、标题、艺术家数组、专辑、曲目版本、时长、封面以及来源引用。ProviderTrackRef 保留 providerId、平台歌曲 ID 和所需的原始识别字段。一个曲目可以关联多个来源，来源标识不替代应用内曲目 ID。

曲目版本明确区分录音室、现场、翻唱、伴奏、混音、原声等。展示信息与平台解析所需字段分别保存。导入或升级时，不以标题单独作为歌曲唯一标识。

ResolvedAudio 区分来源声明的质量与实测媒体属性，包含音源有效期和检查结果。播放地址不作为长期曲目身份；过期后按来源重新解析。

所有跨边界数据在运行时校验结构，编译期 TypeScript 类型不能替代运行时检查。新增可选字段应有默认行为；不兼容的数据变更必须升级契约主版本。

创作项目另外使用 AssetRecord、ProjectRevision、EditPlan、TemplateDefinition 和 BeatMap，不向 Track 里混入生成图片或动画帧。派生素材保留原始素材引用和内容哈希。AI 请求、参数方案、预览和导出任务均绑定具体的素材哈希与项目版本，过期结果不覆盖当前版本。

## 6. 接口版本和能力协商

扩展清单声明扩展 ID、扩展版本、类型、所需宿主接口版本范围、支持的平台和能力。各类契约分别版本化，初始主版本为 1。

相同主版本下新增可选字段或能力需保持既有语义；移除字段、改变字段含义或改变必须实现的方法时升级主版本。宿主拒绝加载不匹配的主版本，并显示所需版本和当前版本。

capabilities 显式声明搜索、整曲解析、歌词、封面、账号访问、可用音质和离线编辑能力。界面和调度器依据能力启用功能，不根据来源名字推测支持情况。

一首歌的可用音质由歌曲元数据、音源能力和实测资源共同决定。音质切换重新解析资源并检查；自动降级必须显示实际档位。不能将 128k 音频转换后标记为原生 FLAC 或 Hi-Res。

## 7. LX 兼容层

LX 脚本通过独立兼容层接入。核心业务使用自己的标准契约；兼容层负责转换平台代码 wy、kg、tx、kw、mg、local、歌曲字段、音质字段和事件。

首版明确验证的兼容基础为 globalThis.lx、EVENT_NAMES、on、send、request 及定时器；脚本所用的其他辅助 API 在兼容清单中逐项列出实现和验证状态。未支持的 API 返回具体的兼容错误，不默默改变返回语义，不宣称支持所有 LX 脚本。

导入时校验脚本信息和初始化结果，执行能力探测。脚本使用受限 JavaScript 执行环境，不直接运行在界面上下文中。独立进程本身不等于文件权限隔离；宿主不得向脚本暴露 require、process、文件系统或其他扩展的账号数据。网络请求通过宿主提供的桥接能力执行。

宿主在脚本执行环境外控制初始化与请求超时，能终止失去响应的执行环境。单个脚本失败时禁用该脚本或该次调用，其余音源和本地音乐继续使用。异常脚本默认不自动更新；替换版本前保留可恢复的原配置。

## 8. 完整曲目、匹配与换源

搜索聚合保持各来源可追溯。缺少可用音源的曲目可以显示具体不可用原因，界面不提供试听播放按钮，也不以片段作为降级资源。

明确的试听标志或试听资源直接排除。其他在线资源在发声前读取媒体信息、核对预期曲目时长；未知或无法可靠检查的资源不得标记为已验证完整。不得简单按“少于 60 秒”判断试听，因为真实曲目也可能很短。

跨平台匹配参考 LX 对歌名、歌手、专辑、版本标记和时长的处理。元数据时长比较首版采用不超过 5 秒的差异；未知时长不能仅靠此条件通过。现场、翻唱、伴奏、混音等版本标记不一致时不自动替换。

实际媒体时长与匹配后的预期时长明显不一致时拒绝该资源并尝试下一个匹配音源。检查针对片段和版本不匹配；元数据与时长无法独立证明音频内容身份，不将该检查描述为内容鉴真。

当前来源失败、链接过期或检查不通过时尝试其他已匹配来源。每次解析记录尝试过的来源与音质组合，限制总时间和重试次数，避免无限循环。手动指定音质可选择严格模式；自动模式允许降到明确显示的实际可用档位。

全部来源不可用时返回“没有可用的完整音源”及具体失败原因。搜索覆盖率和完整播放覆盖率分别验证与报告。

## 9. 数据存储与升级

通过 StorageRepository 访问持久化数据，首版使用本地版本化数据文件，串行写入并原子替换。文件含 schemaVersion；曲库、设置与扩展配置按模块保存。后续更换数据库由存储实现和迁移工具负责，其他模块继续使用同一接口。

每次迁移先保存已知版本的备份，校验输入结构，逐版本转换并校验输出，最后替换正式数据。失败时保留原数据并停止迁移。新版本不会在无法识别旧数据时重建空歌单覆盖原文件。

降级遇到较新的不兼容结构时不写入该结构，可恢复先前备份或使用对应软件版本。播放器配置迁移和音源配置迁移分开处理。

本地导入建立文件引用和索引，支持文件、文件夹与拖拽，读取音乐信息与封面。移除曲库条目不删除原始音乐；编辑导出通过保存对话框生成新的输出文件。

## 10. 状态、并发和故障处理

请求携带 requestId 和取消信号。用户换搜索词、切歌或修改音质后，旧请求结果不会覆盖当前状态。事件包含事件类型、契约版本、资源 ID 和请求 ID。

错误区分接口不可用、需要账号访问、请求限流、版本不兼容、曲目不匹配、资源不完整、链接过期和编码失败。界面显示对用户有意义的原因；内部保留模块 ID 和版本用于定位。

单个平台超时后返回其他平台已有的结果。连续失败的来源暂时停止自动重试，允许手动重试恢复。音源状态按来源分别管理，不把全部在线来源视为一个共享连接。

搜索缓存按来源、查询、分页和账号配置状态区分；播放地址缓存遵循来源有效期。账号配置变化后失效相关缓存。缓存失败不影响使用原始曲库数据。

## 11. 界面与音频功能

界面包括侧边导航、音乐库、搜索结果、专辑和歌单、收藏、固定播放条，以及按需打开的音效编辑面板。主界面以歌曲与操作为中心，不显示与用户决策无关的实现细节。

播放支持暂停、上一曲、下一曲、定位、音量、顺序、随机和单曲循环。首版支持 MP3、FLAC、WAV、M4A 等常见本地格式；实际格式能力以解码检查为准。

编辑功能包含本地音频裁剪、淡入淡出、均衡器、音色预设、混响和速度处理。仅将明确支持离线处理的效果与参数用于导出，不能静默忽略不支持的效果。

音源管理提供来源启停、排序、导入、兼容状态和单源测试。后续增加模块后，界面根据注册信息与能力增加相应入口。

## 12. 验收与兼容回归

- 应用：Windows 程序启动，真实文件导入播放，关闭重开后保留曲库、歌单和设置。
- 搜索适配：三个重点平台分别测试成功、空结果、结构变化、超时和限流；一个来源失败时仍显示其他结果。
- 播放：确认整曲正常播放和末尾定位；拦截已知试听和时长不符资源；真实短曲正常处理；音源失效后换源，版本不一致时拒绝自动替换。
- 扩展契约：运行时输入输出校验、版本不匹配提示、能力启用规则、取消后的旧响应处理，以及 LX 支持 API 的脚本样本。
- 故障隔离：脚本异常或超时后其他音源、本地播放和界面仍可使用。
- 音频：参数调节对声音有实际影响；速度与保持音高行为正确；裁剪、淡入淡出、音效与不同质量的导出文件可重新播放。
- 数据：从上一版样本迁移并校验收藏、歌单与设置，失败时保留原数据，备份可恢复。
- 扩展示例：通过注册额外的模拟来源或简单内置音效证明接入不需要修改 PlayerEngine 核心播放流程。
- 创作模块：执行对应规格中的音频参数校验、撤销恢复、图像锁定区合成、上下 Q 弹限制与节拍同步检查；基础播放器在 AI 服务不可用时继续使用。

接口适配修改时执行对应来源检查；核心播放、存储或 Electron/音频运行时升级时执行相应跨模块回归。实时平台测试与固定样本测试分开，真实完整音源没有通过实测时不报告为已支持。
