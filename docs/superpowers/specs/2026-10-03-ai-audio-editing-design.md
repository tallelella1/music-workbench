# AI 音频分析与参数编辑设计

日期：2026-10-03（Asia/Hong_Kong）

状态：brainstorming 设计讨论稿。用户已选择第一阶段为分析后自动调整 EQ、混响、动态和速度。本阶段不编码，不执行真实音频处理或收费 AI 调用。

主规格：[Windows 音乐播放器设计](2026-10-03-music-player-design.md)。

## 1. 用户体验和成功标准

用户选择一首可编辑的完整音乐，描述目标，例如“低音更饱满，人声清楚一点”或“速度放慢到 0.85 倍，保持音高”。系统分析音频，解释发现的问题，生成具体参数，在独立版本中自动形成可播放的效果预览。用户可调整强度、比较处理前后、撤销和导出。

预览与导出使用用户选择的完整源文件或明确的编辑区间。AI 分析可以使用代表性片段，但片段分析不能被描述为完整歌曲已经逐段检查。每个分析结果记录素材哈希、分析区间、工具与模型版本。

第一阶段不包含人声身份替换、乐器重新演奏或音乐重作曲。这些需求依赖不同的分轨和生成链路，后续通过独立能力接入。

## 2. 方案选择

推荐：本地音频分析提供数值依据，AI 解释用户意图并生成参数方案，本地音频引擎执行。音效可实时预览，参数可检查，修改能够撤销；AI 服务替换不影响基础播放器和导出格式。

另一种方案是直接把音乐提交给生成式音频服务，取得重生成音频。它更适合风格转换或重创作，可能改变演奏细节，对效果的一致性与可解释性要求更高，留作独立扩展。

完全使用本地分析和固定音色预设，也能完成基础调整，但对自由对话目标的解释能力有限。它作为 AI 服务不可用时的手动编辑入口。

## 3. 分析与编辑流程

1. 选择音频、分析区间和目标；显示本次将提交给 API 的音频范围，用户启动该操作即发起分析。
2. AudioAnalysisService 读取格式、采样率、声道、响度、峰值、频谱分布和节拍信息。
3. 如 AIProvider 支持音频输入，提供对应片段和本地指标；仅支持文字的规划服务只接收指标和用户目标，不能宣称直接听过音频。
4. AIEditingPlanner 输出问题解释和结构化 EditPlan。
5. 校验素材版本、处理器能力、参数范围及目标区间，通过后形成派生预览版本。
6. PlayerEngine / EffectChain 执行预览，ExportService 处理用户选定的输出。

对音乐是否明亮、温暖、人声靠前、混响偏多等描述属于听感判断或模型推断。响度、峰值和频谱指标属于本地测量。界面与数据分开呈现，不把推断或模型自评当作客观测量。

## 4. 模块和能力

- AudioAnalysisService：解析完整输入，计算指标并记录区间与分析配置。
- RhythmAnalyzer：提供带来源、置信信息和版本的 BeatMap，供速度建议及音乐视觉同步使用；检测结果允许人工校正半拍、倍拍和偏移。
- AIEditingPlanner：将用户目标、音频证据和可用处理器转为具体编辑操作。
- AudioEffectRegistry：提供实际可用的均衡器、混响、动态处理、限幅和速度处理能力，复用主规格的接口。
- CreativeProjectService：保存源文件引用、方案、预览版本、处理结果及撤销历史。

动态处理会在 AI 音频单元加入压缩器与输出限幅能力。若某个运行环境没有这些处理器，系统明确标注缺失并提供可执行的方案，不静默丢弃操作。

## 5. 参数和操作契约

EditPlan 包含 planVersion、projectId、assetId、assetHash、baseRevisionId、目标时间区间、操作列表、每项说明和所需能力。操作只引用已注册的 effectId 或受支持的速度处理操作，不接受任意脚本、文件路径或命令。

首版参数边界：均衡器各段增益 -12 至 +12 dB，混响比例 0 至 1，速度 0.5 至 2 倍。动态处理参数按已注册处理器的结构和范围校验。预放大与输出峰值补偿作为明确参数记录，不仅通过更大音量制造听感改善。

保持音高作为独立选项。用户只要求音色变化时默认保持速度；用户指定速度或目标节奏时生成速度操作。目标节奏不确定时标注估计，允许用户校正，不通过主观音色判断推定精确 BPM。

AI 推荐的数值是候选参数。系统完成结构检查和能力检查后自动应用到可撤销的预览；结构有效不代表听感必然更好。听感目标含糊时提供少量可选方向，避免对每个低风险参数反复确认。

## 6. 对话编辑与版本

对话命令绑定当前素材、区间、版本和已有音效链。用户说“再温暖一点”“混响减半”“回到上一个版本”，分别转为参数修改、数值运算和版本切换。

已知的数值、区间和单位由应用校验和计算。AI 负责语义判断，不能改写用户已锁定的速度或时间区间。TypeSafe 的封闭动作选择与结构化决策可以作为可选规划能力，第一阶段不强制依赖它，也不将它当作音频识别或生成服务。

对比播放支持响度匹配与关闭匹配两种明确状态。历史版本保留实际参数和已经生成的资源；恢复历史不重新调用模型。基准版本改变后的旧分析或旧方案不会自动应用。

## 7. API 和任务生命周期

AIProvider 按音频理解、文字规划、结构化结果和任务查询分别声明能力。服务接入由独立适配器处理，厂商特定字段不进入 EffectChain。

API 密钥由桌面宿主管理，通过系统提供的受保护存储保存，不写入歌单、模板或普通项目导出文件。请求只包含当前操作需要的素材和上下文，音源脚本不能读取 AI 服务配置。

分析任务具有 requestId、状态、取消标记和对应项目版本；状态为等待、分析、规划、校验、预览完成、失败或取消。重复操作复用可用分析结果，缓存按素材哈希、区间、配置与模型版本区分。

取消或超时不会让迟到结果覆盖项目。远程服务支持查询时保存任务 ID 再查询结果；不支持查询或幂等的生成请求不进行盲目自动重发。展示提供方能够返回的实际用量，未知的费用不填成零。

## 8. 错误处理和后续验收

AI 服务不可用时，基础播放和手动音效编辑继续可用。格式无法解析、分析区间超限、能力缺失或参数不合法时显示具体问题。使用同一 API 协议不等于同一音频能力，接入后逐项验证。

后续验收包括参数范围、素材版本校验、变速保持音高、非破坏性编辑、撤销恢复、原始与处理后响度对比、效果导出、异常服务降级及节拍人工校正。模型评估使用有代表性的不同音乐风格、噪声和短音频样本，不仅验证返回结构。

成功标准：编辑前后的差异可听、可解释，参数与导出一致，撤销能恢复原状态，AI 失效不影响基础播放器。模型自评或概率不作为完成这些检查的替代。
